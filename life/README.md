# 人生的意义 · 卡点视频（纯 JavaScript）

成片：[`build/life.mp4`](build/life.mp4)，规格为 1920×1080、30fps、H.264 + AAC，时长 60 秒。

画面、音乐和渲染全部用 JavaScript 完成，没有任何音频文件或素材。

| 文件 | 作用 |
| --- | --- |
| `src/score.js` | **唯一的时间轴**：100 BPM，列出每一个鼓点、音符、字幕的时刻 |
| `src/audio.js` | 用 Web Audio API（OfflineAudioContext）按 `score.js` 合成全部音乐，包括鼓、钢琴、贝斯、Pad、旋律、铃声、雨滴和烟花 |
| `src/visuals.js` | 用 Canvas 按同一份 `score.js` 绘制画面，所有闪光、跳跃、脚印、涟漪和字幕都由事件列表驱动 |
| `index.html` | 浏览器打开后点“▶ 播放”，会先实时合成音乐，再用音频时钟驱动画面 |
| `render.mjs` | 用 Node + Playwright 逐帧渲染并用 ffmpeg 合成 MP4，最后自动做卡点精度检测 |

```bash
cd life
node render.mjs            # 渲染 build/music.wav 和 build/life.mp4，并输出卡点检测报告
node render.mjs --check    # 只对现有文件重新做卡点检测
```

## 为什么能准确踩点

1. **画面和声音读同一份事件表。** 例如 `SCORE.kick` 里的每一个时刻，既是合成器发出鼓声的采样点，也是画面闪光、小光点落地、留下脚印的时刻，两者不存在各自计时后慢慢漂移的问题。
2. **节拍对齐整帧。** 100 BPM 下一拍是 0.6 秒，在 30fps 下正好是 18 帧，所以每一拍都落在整帧上。
3. **踩点精度会实际测量。** 渲染器会把成片 MP4 里的音频解码出来，逐个检测底鼓和心跳的起音位置，再与乐谱时刻比较。测量前先用同一套乐器单独渲染的鼓点校准掉检测器本身的延迟。最近一次的结果：
   - 65 个鼓点和心跳中，64 个误差在 ±5ms 以内；
   - 中位误差 0.5ms，最大误差 10.7ms；
   - 相比之下，人耳能察觉的音画错位大约在 20–40ms 以上。

## 分段（每段 4 小节，一小节 2.4 秒）

| 时间 | 段落 | 卡点方式 |
| --- | --- | --- |
| 0–9.6s | 问 | 心电图的每一次心跳都对应一声“咚-咚”；“人、生、的、意、义”五个字逐拍砸下，每字一声铃；最后一次心跳化作一个光点，生命由此开始 |
| 9.6–19.2s | 童年 | 光点每拍跳一步，落地的瞬间对应一次轻鼓并留下一个脚印；歌词依次是“第一次睁开眼”“叫出妈妈”“摔倒”“然后站起来” |
| 19.2–28.8s | 青春 | 四拍子底鼓，**每一拍硬切一次画面并换一个词**，从“奔跑”一路到“火焰” |
| 28.8–38.4s | 低谷 | 半速节奏，下雨。每一声雨滴都对应地面上的一圈涟漪；“直到有一天”随军鼓滚奏逐字出现，最后一拍全黑静音 |
| 38.4–48s | 答案 | 副歌高潮。第 1、3 拍放烟花，歌词随八分音符的钢琴琶音逐字打出：“意义，是你爱过的人……和你留下的光” |
| 48–57.6s | 传承 | 鼓声逐渐退去，每一拍点亮一盏新的光，并伴一声铃；字幕为“意义不是被找到的，而是被活出来的。” |
| 57.6–60s | 尾声 | 最后一次心跳，出现片名“人生的意义”和“—— 愿你，活出自己的答案” |
